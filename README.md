# tf-import-block-gen

[![ci](https://github.com/moveeeax/tf-import-block-gen/actions/workflows/ci.yml/badge.svg)](https://github.com/moveeeax/tf-import-block-gen/actions/workflows/ci.yml)
[![Go](https://img.shields.io/badge/go-1.22%2B-00ADD8?logo=go&logoColor=white)](https://go.dev)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Turns a Terraform plan into ready-to-paste `import` blocks. It reads the plan JSON,
reads an inventory of what already exists in the account, matches the two by name and
tags, and writes the Terraform 1.5 `import` blocks — with the id format each resource
type actually expects.

No cloud API is ever called, so it runs in CI with no credentials.

## The problem

`terraform plan` says *create 38 resources*. The account says they are all already
there. The fix is thirty-eight hand-typed `terraform import` commands, each needing a
provider-specific id format you look up one at a time: an `aws_instance` takes `i-abc`,
an `aws_iam_role` takes the role **name** (not the ARN), an `aws_sqs_queue` takes the
queue **URL**, an `aws_route53_record` takes a `ZONEID_name_TYPE` triple. Every mistake
puts the wrong object in state.

The plan already knows every address and the attributes the config asked for. The
account already knows the real ids. Nothing joins them. This does.

## Install

```sh
go install github.com/moveeeax/tf-import-block-gen/cmd/tf-import-block-gen@latest
```

Or build from a checkout:

```sh
go build -o tf-import-block-gen ./cmd/tf-import-block-gen
```

## Usage

```sh
terraform plan -out tfplan
terraform show -json tfplan > tfplan.json

tf-import-block-gen --plan tfplan.json --inventory live.json > imports.tf
```

Import blocks go to **stdout** (or `--out`); the report goes to **stderr**. That split
is what makes the redirect above safe.

Real output from `examples/`:

And the `imports.tf` it wrote:

```hcl
# Generated by tf-import-block-gen. Review before `terraform apply`.

import {
  to = aws_s3_bucket.assets
  id = "acme-assets-prod"
}

import {
  to = aws_iam_role.app
  id = "acme-app-task"
}

import {
  to = aws_cloudwatch_log_group.app
  id = "/acme/app"
}

import {
  to = aws_sqs_queue.jobs
  id = "https://sqs.eu-central-1.amazonaws.com/123456789012/acme-jobs"
}

import {
  to = aws_route53_record.apex
  id = "Z1D633PJN98FT9_acme.example.com_A"
}
```

Note what happened to the ids: the inventory held `arn:aws:s3:::acme-assets-prod`,
`arn:aws:sqs:eu-central-1:123456789012:acme-jobs` and a bare record name. Terraform
wants a bucket name, a queue URL and a `ZONEID_name_TYPE` triple. That translation is
the point of the tool.

Resolve the ambiguity by hand and the run goes green:

```sh
tf-import-block-gen --plan examples/tfplan.json --inventory examples/live.json \
  --map aws_instance.web=i-0abc123def4567890
```

## The inventory file

JSON, either a top-level array or `{"resources": [...]}`:

```json
[
  {
    "type": "aws_s3_bucket",
    "id": "arn:aws:s3:::acme-assets-prod",
    "name": "acme-assets-prod",
    "region": "eu-central-1",
    "account_id": "123456789012"
  }
]
```

Or CSV with a header row (`type` and `id` required; `tags` uses `k=v;k=v`):

```csv
type,id,name,tags,region,account_id
aws_instance,i-0abc123def4567890,,Name=acme-web;env=prod,eu-central-1,123456789012
```

`region` and `account_id` are optional, but they are what lets the tool rebuild an
`aws_sqs_queue` URL or an `aws_iam_policy` ARN from a bare name. Any resource lister
works as a source — `aws resourcegroupstaggingapi get-resources`, Steampipe, a Config
snapshot, a CSV someone exported from the console.

## How matching works

Per planned create, in order, and only against inventory entries of the same type:

1. `--map <address>=<id>` — an explicit override, which wins over everything.
2. **Exact name.** The planned name (from `name`, `bucket`, `queue_name`, … or the
   `Name` tag) equals the entry's `name` or `Name` tag, case-insensitively.
3. **Address name.** The resource name in the plan address matches, with `-` and `_`
   treated as the same character, so `aws_instance.web_server` finds `web-server`.

The first stage that hits anything wins, so a loose address match never dilutes a
strong name match into an ambiguity. **Two or more candidates is reported, never
guessed** — picking wrong writes the wrong object into state, and `terraform state rm`
is another manual step. A create with no candidate is reported as genuinely new, not as
an error.

A resource being replaced (`delete` + `create`) is skipped: it is already in state.

## Id formats

`--list-types` prints the types with a verified id format. Today:

`aws_instance`, `aws_vpc`, `aws_subnet`, `aws_security_group`, `aws_internet_gateway`,
`aws_nat_gateway`, `aws_s3_bucket`, `aws_iam_role`, `aws_iam_user`,
`aws_iam_instance_profile`, `aws_iam_policy`, `aws_dynamodb_table`,
`aws_ecr_repository`, `aws_cloudwatch_log_group`, `aws_sqs_queue`,
`aws_route53_record`.

An unknown type still gets a block, with the raw id and a comment saying the format was
not verified:

```hcl
# id format for cloudflare_record is not verified -- check it before applying
import {
  to = cloudflare_record.apex
  id = "a1b2c3d4e5f60718293a4b5c6d7e8f90"
}
```

Unusable output would be worse than a flagged guess you can check in thirty seconds.

## Flags

| Flag | What it does |
| --- | --- |
| `--plan` | `terraform show -json` output; `-` reads stdin |
| `--inventory` | live resources, `.json` or `.csv`; `-` reads stdin |
| `--out` | write blocks to a file instead of stdout |
| `--map` | `<address>=<id>` override, repeatable |
| `--only` | comma-separated types to consider |
| `--skip` | comma-separated types to ignore |
| `--format` | report format: `table` (default) or `json` |
| `--strict` | exit 1 when any planned create stays unmatched |
| `--list-types` | print the types with a verified id format |

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | every planned create was matched or is genuinely new |
| 1 | an ambiguous match exists, or `--strict` and something is unmatched |
| 2 | the plan or inventory could not be read |

## In CI

`--format json --strict` makes a usable gate: fail the pipeline when a plan wants to
create something that is already in the account.

```yaml
- name: no accidental re-creates
  run: |
    terraform show -json tfplan > tfplan.json
    tf-import-block-gen --plan tfplan.json --inventory live.json \
      --format json --out imports.tf
```
